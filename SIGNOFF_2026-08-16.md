## 1 · The triangular conflict — Reading A / B / C

**Recommendation: adopt C.** But **not for the reason the report gives.**

### The stated justification is circular

The report justifies C by the 2022-10-03 benchmark entry `0.98342`, a London bar.
That field's provenance:

```

```

**The trader confirmed the outcome, not the entry.** `0.98342` is marked VERIFIED

produced by C.**

Worse, the one field the trader *did* confirm — `+5R` — is the field §0.0a proves
unreachable. On benchmark #1 there is currently **no independently confirmed field

### Benchmark #2 does discriminate, and it is not circular

`eurusd-2022-10-03-london-to-new-york-short-sweep`. Trader-confirmed field:
**outcome = −1R**, and unlike benchmark #1 that outcome **is reachable** on the
fixture.

```

READING A          TREND SHORT  entry 0.97900  -> setup MISMATCH, entry off 28.1 pips
                   replay: filled 14:00Z, STOP_LOSS -1.000R

READING B/C        SWEEP SHORT  entry 0.98181  -> setup MATCH, entry EXACT, outcome MATCH
```

Reading A reaches −1R **by a different route** — a TREND midpoint entry 28 pips
away. It matches the number and misses the trade. Only the execution-window reading

Reading A does not implement the diagram.**

The Session Top *is* the session's highest high, so nothing inside the session can
pierce beyond it. Under A the sweep test is self-referential and `RANGE SETUP` is
dead code — 0 of 1030 trades. This holds independently of any benchmark.
